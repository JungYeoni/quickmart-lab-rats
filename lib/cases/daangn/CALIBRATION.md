## 스펙과 다르게 한 결정 (PR에도 기재)
1. **UNDERPOWERED 규칙**: 시나리오 #4는 표본이 매우 커서 통계적 검정력이 높게 나온다. 참 효과가 MDE의 25% 미만이면 달성 검정력을 0.25로 제한해, 설계가 의도한 질문에 답하지 못한 경우를 잡는다.
2. **p2는 p1 설계를 이어받음**: s5에서 거래후기 설계 칸(배정 시점·분석 모집단·지표 등)은 선택 입력이고, 비어 있으면 안내와 함께 거부한다.
3. **A/A 실행**은 설계에서 `run_aa_first`(p1) / `rerun_aa`(p2)를 고르지 않았으면 거부한다.
4. **진단 패널 게이트**: 플랫폼 진단(설치 코호트·양쪽 그룹 중복)은 A/A에서는 바로 열리고, 본 실험에서는 UI의 "조사하기" 버튼 뒤에 둔다. 데이터는 API 응답에 포함된다(숨김 정보는 아님).
5. **`meta` 패널 추가**: UI가 A/A 여부와 플랫폼을 알 수 있도록 `{aa, platform|unit}`을 내린다.
6. 이 사례는 모집단이 크고 셀 단위(유형 × SDK)로 이항 표본을 만드는 방식이다. 토스처럼 사용자 모멘트 닫힌 형태가 아니다.
